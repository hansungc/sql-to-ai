# 자주 묻는 질문

실습하다 자주 만나는 상황을 모았습니다. 여기에 없으면
[Q&A 게시판](https://github.com/hansungc/sql-to-ai/discussions/categories/q-a)에 남겨 주세요.

## 결과가 책과 다를 때

### 행 순서가 책과 다릅니다

`ORDER BY` 없이 `LIMIT`만 쓴 예제, 그리고 같은 값이 여러 행에 있을 때(동순위)는
**행 순서가 실행할 때마다 달라질 수 있습니다.** SQL 표준이 순서를 보장하지 않기 때문이며,
오류가 아닙니다. 값 자체가 맞으면 정상입니다.

1주차 초반과 2주차의 정렬 예제에서 특히 자주 보입니다.

### MCP로 조회하면 날짜가 하루 앞으로 나옵니다

클로드 코드가 MCP로 받아 온 `DATE` 값은 UTC 기준 ISO 문자열로 바뀝니다.
`2026-07-22`가 `2026-07-21T15:00:00.000Z`처럼 보입니다(한국 시간과 9시간 차이).

값과 순서가 맞으면 정상입니다. 날짜를 그대로 보고 싶으면 조회 칼럼을 바꿔 달라고 하세요.

```sql
SELECT DATE_FORMAT(s.stream_date, '%Y-%m-%d') AS stream_date, ...
```

터미널에서 `mysql`로 직접 조회하면 `2026-07-22` 그대로 나옵니다.

### AI가 "주문 금액이 안 맞는다"고 합니다

`orders.total_amount`가 `quantity × products.price`와 다른 주문이 234건 중 21건 있습니다.
검증을 시켜 보면 AI가 이 차이를 찾아내 보고하는데, **데이터 오류가 아닙니다.** 실제 주문
테이블에서 결제액은 할인·쿠폰·구매 시점 가격 때문에 정가 곱셈과 어긋납니다.

**매출은 `total_amount`로 셉니다.** 교재의 모든 예제와 기대값(`552000`, `2732000` 등)이
`SUM(o.total_amount)` 기준입니다. `quantity × price`로 다시 계산하면 값이 달라집니다.

### `VERSION()` 결과가 책과 다릅니다

MySQL 버전에 따라 다르게 나오는 것이 정상입니다. 예제 파일은 **8.4.10** 기준으로 검증했습니다.

db-fiddle은 목록에 `9`, `8`처럼 메이저 번호만 표시하고, 그 안에서 실제로 붙는 버전은
서비스 쪽에서 정합니다. 어떤 버전인지는 `SELECT VERSION();`으로 확인하세요.
본편(0~4주차)과 부록은 8과 9 어디서든 그대로 동작합니다 — MySQL 9에서 제거된
`MD5()` 같은 함수를 쓰지 않기 때문입니다. `MD5()`는 5주차 Day 25에서만 씁니다.

## 오류가 날 때

### 환경 셋업 행 수 확인에서 `Unknown column 'artists' in 'field list'`

교재 436쪽의 행 수 확인 SQL에서 테이블 이름이 작은따옴표가 아니라 백틱으로 조판됐습니다.
MySQL이 백틱을 칼럼 이름으로 읽어 생기는 오류이며, [정오표](정오표.md)에 등록해 두었습니다.

바로 쓸 수 있는 SQL은 `5주차/환경셋업/도커로_MySQL_준비하기.md` 3단계에 있습니다.
작은따옴표로 바꿔 실행하면 됩니다.

```sql
SELECT 'artists' AS table_name, COUNT(*) AS row_count FROM artists
UNION ALL SELECT 'fans', COUNT(*) FROM fans;
```

### 부록 N에서 `Table 'query_history' already exists`

부록 N과 5주차가 이름은 같고 칼럼이 다른 `query_history`를 각각 만듭니다.
5주차 도커로 환경을 만들었다면 이미 5주차용 테이블이 있어 부록 N의 `CREATE`가 실패하고,
이어지는 `INSERT`·`SELECT`도 `Unknown column 'created_at'`으로 실패합니다.

**의도된 충돌이며 해결책 세 가지가 `부록/appendix_N.sql` 첫머리에 적혀 있습니다.**
가장 간단한 방법은 부록 N을 별도 DB에서 실습하는 것입니다.

```sql
CREATE DATABASE appendix_db;
USE appendix_db;
```

### 부록 F에서 `Duplicate key name`

`CREATE INDEX`를 두 번 실행하면 납니다. 다시 실행하려면 먼저 지우세요.

```sql
DROP INDEX idx_streaming_fan_id ON streaming;
```

외래 키가 쓰는 자동 인덱스 `fan_id`는 지울 수 없습니다 — 정상입니다.

### `FUNCTION MD5 does not exist`

MySQL 9에서 `MD5()`가 제거됐습니다. Day 25 평가셋은 8.x에서 실행하세요
(도커 환경은 8.4로 고정돼 있습니다). 대안은 `5주차/day25/day25.md`의 SHA-256 안내를
참고하세요.

### 한글이 깨져서 나옵니다

데이터베이스를 만들 때 문자셋을 지정하지 않으면 생깁니다.

```bash
mysql -u [사용자] -p -e "CREATE DATABASE harmony_db
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -u [사용자] -p --default-character-set=utf8mb4 harmony_db < 0주차/harmony_v1.sql
```

도커로 준비하면 `mysql-utf8mb4.cnf`가 자동 적용돼 신경 쓸 필요가 없습니다.

## 5주차 환경

### `docker compose up -d`가 바로 실패합니다

```
required variable MYSQL_ROOT_PASSWORD is missing a value: 환경셋업/.env에 MYSQL_ROOT_PASSWORD를 설정하세요
```

의도된 안내입니다. `5주차/환경셋업/.env.example`을 `.env`로 복사하고 비밀번호를 바꾸세요.
`.env`는 `.gitignore`에 들어 있어 커밋되지 않습니다.

### 3306 포트가 이미 쓰이고 있습니다

`5주차/환경셋업/.env`의 `HARMONY_DB_PORT`를 `13306` 같은 값으로 바꾸세요.
`5주차/harmony-analysis/.env`에도 **같은 값**을 적어야 MCP가 붙습니다.

### 훅이 아무 반응도 없습니다

`jq`가 설치돼 있어야 합니다(`jq --version`으로 확인). 그리고 `matcher`에 `Bash`와
`mcp__harmony_db__execute_sql`이 **모두** 들어 있어야 터미널 쿼리와 MCP 쿼리에 함께 걸립니다.
동작을 확인하려면 Bash로 `mysql -e "..."`를 실행해 보세요.

## Windows에서 실습할 때

### 설치했는데 `claude` 명령을 찾을 수 없습니다

```
'claude' 용어가 cmdlet, 함수, 스크립트 파일 또는 실행할 수 있는 프로그램 이름으로 인식되지 않습니다.
```

설치 스크립트가 `claude.exe`를 `%USERPROFILE%\.local\bin`에 두기만 하고 `PATH`에는 넣지
않습니다. 아래 한 줄을 실행한 뒤 **새 터미널**을 여세요.

```powershell
[Environment]::SetEnvironmentVariable('Path', "$env:USERPROFILE\.local\bin;" +
  [Environment]::GetEnvironmentVariable('Path','User'), 'User')
```

### `git rev-parse`에서 오류가 납니다

ZIP으로 내려받아 Git이 없는 경우입니다. 각 Day 첫머리의 `git rev-parse` 두 줄 대신
압축을 푼 저장소 루트로 직접 이동하세요. `git check-ignore` 확인도 건너뛰면 됩니다.

`check-environment.ps1`이 Git 유무를 확인해 `WARN`으로 알려 줍니다.

### Day 24~25가 진행되지 않습니다

훅 3종이 Bash 스크립트라 PowerShell에서는 실행되지 않습니다. **WSL이나 Git Bash에서
클로드 코드를 실행**하세요. Day 21~23은 Windows 네이티브에서 그대로 진행됩니다.

자세한 전환 방법은 `5주차/day24/day24.md` 첫머리에 있습니다.
