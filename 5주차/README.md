# 5주차 실습자료

이 폴더는 교재 5주차를 읽으며 사용하는 **실습 보조자료**입니다. 교재의 개념과 해설을 대신하지 않습니다. 독자가 지면의 긴 코드·SQL·프롬프트를 다시 타이핑하지 않도록 Day별 한 파일에 실습 순서대로 모았고, macOS·Linux·Windows의 설치 차이와 실행 오류 해결만 덧붙였습니다.

## 실습 환경에서만 진행합니다

5주차는 **실습 전용 데이터베이스**를 전제로 합니다. 도커로 새로 띄운 `harmony_db`, 또는 지워도 곤란해질 일이 없는 개인 학습용 MySQL에서 진행하세요.

Day 22부터 클로드 코드가 MCP로 데이터베이스에 직접 붙습니다. 이어서 Skill과 서브에이전트가 쿼리를 만들어 실행하고, Day 25에서는 그 과정을 cron에 걸어 정해진 시각에 자동으로 돌립니다. 사람이 매번 확인하지 않는 구간이 생깁니다.

그래서 **운영 중인 회사·서비스 데이터베이스에는 연결하지 마세요.** 개인정보가 들어 있거나, 여러 사람이 함께 쓰거나, 되돌릴 백업이 없는 데이터베이스도 마찬가지입니다.

## 사용 순서

1. 교재에서 해당 예제의 설명을 읽습니다.
2. 아래 Day 문서에서 같은 상위 제목과 쪽수를 찾습니다.
3. `프롬프트`, `코드`, `SQL`, `실행` 블록을 차례대로 복사합니다.
4. 각 예제의 짧은 `확인` 항목만 대조합니다.
5. 오류가 날 때만 `막힐 때`를 읽습니다.

코드 블록의 실행 위치는 언어 표시로 구분합니다. `bash`·`powershell`은 운영체제 터미널, `text`는 Claude Code 입력창, `sql`은 바로 앞 문장에서 지정한 관리자 MySQL 또는 `harmony_db` MCP에서 실행합니다. Claude Code 입력창에서 터미널 명령으로 바꿀 때는 `/exit`하거나 새 터미널 탭을 엽니다.

## 폴더 구조

```text
5주차/
├── day21/day21.md                    # Day 21 복사·실행 자료
├── day22/day22.md                    # Day 22 복사·실행 자료
├── day23/day23.md                    # Day 23 복사·실행 자료
├── day24/day24.md                    # Day 24 복사·실행 자료
├── day25/day25.md                    # Day 25 복사·실행 자료
├── harmony-analysis/                 # 독자가 Claude Code로 완성할 프로젝트
└── 환경셋업/                          # MySQL과 환경 점검 보조자료
```

`harmony-analysis/CLAUDE.md.example`, Skills, 서브에이전트 파일은 본문을 비워 두고 **채울 자리를 `<!-- TODO: ... -->` 주석으로 표시**해 두었습니다. 무엇을 써야 하는지 주석에 적혀 있으니, 본문을 쓰면서 그 주석을 지우면 됩니다. 모두 `.example` 확장자라 해당 Day에서 복사하기 전에는 Claude Code가 자동으로 읽거나 호출하지 않습니다. Day 23·24·25의 프롬프트로 직접 완성하고 교재와 대조합니다.

파일명이 `.example`로 끝나는 설정, Skill, 서브에이전트는 자동 적용되지 않는 안전한 견본입니다. 해당 Day에서 안내할 때만 실제 파일명으로 복사합니다.

각 Day 끝의 `ready` 검사는 DB 연결만 보지 않습니다. 그날 완성해야 할 파일에 `TODO` 주석이 그대로 남아 있는지도 함께 확인하죠. 복사만 하고 아직 채우지 않았다는 뜻이니까요. Day 25에서는 현재 데이터 해시까지 맞춰 봅니다. 실패한 항목을 남긴 채 다음 Day로 넘어가지 마세요.

## 시작 전

저장소 루트에서 환경만 먼저 확인합니다.

macOS·Linux·WSL:

```bash
chmod +x 5주차/환경셋업/check-environment.sh
5주차/환경셋업/check-environment.sh 21 preflight
```

Windows PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File ./5주차/환경셋업/check-environment.ps1 -Day 21 -Phase preflight
```

Day 22에서 MySQL이 필요해지면 [도커로 MySQL 준비하기](환경셋업/도커로_MySQL_준비하기.md)를 따릅니다. 이미 MySQL 8.4와 `harmony_db`가 준비되어 있으면 Docker 단계는 건너뛰어도 됩니다.

## 실행 환경 기준

- 데이터베이스: MySQL `8.4.10` (교재 437쪽 기준은 8.0 이상. 도커는 8.4로 고정했고 8.0에서도 동작합니다)
- MCP 예제: Node.js `22.5.0` 이상, `@bytebase/dbhub@1.2.3`
  (교재 452쪽이 예로 든 서버입니다. 버전을 고정해 화면이 달라지지 않게 했고, 다른 MySQL용
  MCP 서버를 골라도 됩니다 — 그 경우 환경 변수 이름은 그 서버의 README를 따릅니다)
- 훅: Bash와 `jq`; Windows의 Day 24·25는 WSL에서 진행
- 검증 기준일: `2026-09-03`

모든 명령은 macOS Apple Silicon에서 실제로 실행해 확인했습니다. Linux도 같은 Bash 흐름이라 그대로 따라오면 됩니다. Windows는 네이티브 환경에서 Day 21~23까지 진행할 수 있고, Bash 훅이 필요한 Day 24~25는 시작하기 전에 WSL 터미널로 옮기세요. 화면이나 CLI가 버전에 따라 다르면 각 Day의 `막힐 때`에서 현재 명령을 확인하면 됩니다.

## 비밀값과 안전

- `강력한_비밀번호`, `비밀번호`, `실제_비밀번호`, `/절대/경로`는 반드시 바꾸는 자리 표시자입니다.
- 추적 중인 `.example`은 직접 수정하지 않습니다. `.env`, `*.sql.local`, 실제 `.mcp.json`, 실행 로그는 Git에서 제외됩니다.
- 분석용 `claude_readonly`에는 `SELECT`만 줍니다.
- `fans.email`은 `claude_readonly`의 칼럼 권한에서도 제외합니다.
- 훅은 Bash와 `harmony_db` MCP 호출을 검사하지만 보조 장치입니다. 최종 데이터 보호는 MySQL 계정 권한으로 보장합니다.
- 데이터 초기화 명령은 [환경 보조문서](환경셋업/도커로_MySQL_준비하기.md)의 경고를 확인한 뒤에만 사용합니다.
